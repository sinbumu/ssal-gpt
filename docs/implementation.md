# 구현 및 검증 상태

기준: 2026-11-09. 설계 문서의 전체 로드맵과 현재 구현을 구분한다.

## SNS 로그인 유지·브라우저 호환성 보완

- 네이버 진입 버튼을 로그인 폼 URL에서 홈으로 바꿨다. 로그인 폼을 다시 열었다는 사실과 실제 로그아웃을 구분하며, 홈의 로그인/로그아웃 표시를 확인한다.
- 수동 로그인 중에는 JavaScript 확인 대화상자를 자동으로 닫지 않는다. 기존의 일괄 dismiss는 사용자 확인을 방해할 수 있었다. 이것이 특정 사이트의 로그인 유지 실패 원인이었다고 단정하지는 않는다.
- 선택된 탭을 닫은 뒤 남아 있는 탭을 다시 선택하거나 새 탭을 만든다. 오래된 관찰과 작업 소유권은 무효화한다. 대시보드의 정상 종료 버튼은 브라우저 컨텍스트를 종료해 디스크 저장을 마친다.
- 설치된 Google Chrome을 공식 `channel: 'chrome'`으로 선택할 수 있다. 기존 Chromium의 `browser`와 Chrome의 `browser-chrome`은 서로 다른 앱 전용 프로필이다. 평소 사용하는 Chrome 프로필을 복사하거나 연결하지 않는다. 작업은 생성 당시 브라우저에 고정되어 다른 로그인으로 재개되지 않는다.
- ‘현재 로그인 화면 확인’은 보이는 로그인/로그아웃 표시 또는 브라우저 거부 문구만 분류한다. 계정 이름·쿠키 값·페이지 텍스트는 반환하지 않으며, 모호하면 미확인으로 표시한다. 쿠키 존재를 로그인 성공으로 취급하지 않는다.
- Google의 브라우저 보안 거부에는 일반 브라우저에서 직접 여는 경로를 제공한다. 이 경로는 수동 참여용이며 자동화 창으로 로그인 쿠키를 가져오지 않는다. Chrome 채널 선택도 Google 로그인 성공을 보장하지 않는다.

실제 Chromium 재실행에서 합성 영구 쿠키·localStorage 유지, 세션 쿠키의 정상 만료, 수동 확인창 보존, 닫힌 탭 복구를 검사했다. 설치된 Chrome의 별도 프로필과 Chromium으로 돌아왔을 때 기존 데이터 유지도 로컬에서 통과했다. 브라우저를 위장하거나 보안 설정을 끄는 방식은 적용하지 않았다.

사용자 재검증 결과 (2026-11-08, 사용자 보고): 네이버는 수정 후 전용 브라우저를 정상 종료하고 다시 열어도 로그인 상태가 유지됐다. YouTube는 전용 Chromium과 설치된 Chrome 자동화 경로 모두 같은 보안 안내로 로그인이 거부됐으며, 일반 브라우저 직접 열기 경로에서만 로그인됐다. 따라서 해당 환경의 YouTube 로그인 필요 작업은 현재 수동 참여 경로로 취급한다. 일반 브라우저의 성공을 에이전트 로그인 연동 성공으로 기록하지 않는다. 이 결과는 해당 환경의 사용자 보고이며 모든 계정·기기에서의 동작을 보장하지 않는다.

확인한 공식 근거 (2026-11-08): [네이버 로그인 상태 유지](https://help.naver.com/service/5640/contents/19013?lang=ko), [Google의 지원 브라우저 및 자동화 브라우저 차단 안내](https://support.google.com/accounts/answer/7675428?hl=ko), [Playwright 지속 프로필](https://playwright.dev/docs/api/class-browsertype#browser-type-launch-persistent-context), [설치된 Chrome 채널](https://playwright.dev/docs/browsers#google-chrome--microsoft-edge).

## 자율 설문 실행 — 새 구현

대시보드의 **프로필·위임 정책**에서 기본 정보를 저장하고, 추천 자동 적용·선호/일반 평가 기준·단일 선택 충돌 처리·최종 제출·복구 횟수를 정한다. 새 응모를 시작할 때 해당 사이트에 한정된 24시간 위임을 만든다. 정책 변경은 기존 작업의 위임을 만료시키며, 사용자가 작업 카드에서 새 정책을 적용해야 재개된다. 예전 실설문의 개인정보·답변을 프로필에 자동 이식하지 않는다.

- `src/autonomy.ts`: 로컬 프로필, 정책, 출처/질문별 답변 재사용. 기본은 정확한 질문 일치이며, 선호의 의미 재사용은 별도 설정을 켠 경우에만 적용한다. 새 경험·자격은 질문하고 최초 동의를 자동 생성하지 않는다. 질문 의미는 모델 해석에 의존하며, 실행기는 알려진 개인 정보·경험·자격·동의 표현을 추가 검사한다.
- `src/forms.ts`: 현재 렌더링된 네이티브 입력·라디오·체크박스·select 구조를 읽고 실제 입력 전마다 다시 연결한다. 입력 상태를 검증하며, 조건부 질문·전송 대상·선택지 변화 시 남은 계획을 중단한다. label로 가려진 컨트롤도 상태를 확인하며 조작한다.
- `src/autonomous-runner.ts`: 전체 페이지 스크린샷과 폼 구조로 한 번의 답변 계획을 받고, 로컬 값 참조 해석 → 확인함 → 묶음 실행 → 중간 진행/최종 증거 확인을 연결한다. 조건부 문항과 형식 오류는 설정된 복구 한도 안에서 재관찰한다. 결과 불명 제출은 재시도하지 않는다.
- 확인함은 같은 페이지의 모르는 문항을 모아 추천 전체 선택·수정·한 번에 답변/재개를 지원한다. 재사용은 사용자가 선택한 경우 해당 사이트에 저장한다. 정책 밖 질문은 대기하며, 이미 공개되지 않은 미래 페이지를 임의 답변으로 넘겨 읽지 않는다.
- 미제출 확인 뒤 일시정지 상태로 바뀐 작업이 과거 실행 기록으로 숨겨지던 화면 오류를 수정했다. 완료·중지 전의 작업은 진행·확인함에 남고, 일시정지·실패·직접 확인 필요 상태는 확인할 일 수에 포함된다. 합성 브라우저에서 미제출 확인 → 같은 카드의 현재 화면 재개 → 동의 확인함까지 검증하며, 페이지 재탐색이나 답변 전송이 발생하지 않는지 검사한다.
- 개인 값은 로컬 실행기가 입력하고 모델 문맥에는 프로필 키만 제공한다. 입력 칸과 알려진 개인 값의 표시 영역을 스크린샷에서 가린다. 관측 URL·링크·제목을 포함한 모델 문맥에서도 알려진 원문/URL 인코딩 값을 제거한다. 최종 확인 폼 값은 로컬 대시보드에만 표시한다. 보호된 SQLite는 암호화 DB가 아니므로 해당 OS 계정/파일 권한에 의존한다.
- `src/autonomy-demo.ts`: 가상 정보만 사용하는 5페이지 설문. 바뀐 배치, 무작위 필드 이름, 단일/복수 안내 충돌, 동적 추가 질문, 반복 질문, 접수 결과를 포함한다. 확인함 버전은 알 수 없는 사실 2개를 추가한다. 실제 사용자 프로필과 답변 메모리를 오염시키지 않는다.

현재 자동 폼 경로는 네이티브 폼 중심이다. 사용자 정의 위젯·iframe 폼·한 화면의 여러 폼·불명확한 다음 단계·인증은 직접 확인으로 넘긴다. SNS 버튼은 전용 브라우저의 사전 로그인 진입점이며, 현재 화면의 일부 로그인 표시는 분류하지만 SNS별 세션 유효성의 완전한 판별과 좋아요/팔로우 자율 실행은 아직 검증하지 않았다. 탐색 후 후보 자동 선택·예약 운영·당첨 확인은 별도 후속 범위다.

검증 수치는 아래 자동 검증 및 실제 AI 실행 기록으로 구분한다. 합성 드라이버 성공을 실제 AI의 자율성 증거로 간주하지 않는다.

### 실제 ChatGPT 자율 실행 기록 (2026-11-08)

연결된 ChatGPT의 `gpt-6.1-sol`에 실제 페이지 PNG와 폼 구조를 보내 실행했다. 전용 Chromium에서 가상 프로필을 입력하고, 매 실행마다 새로 생성된 필드 이름과 접수 건을 사용했다. 정해진 문항 답을 반환하는 테스트 드라이버가 아니다.

| 시나리오 | 경과 시간 | AI 판단 | 확인함 | 자동 복구 | 입력/출력 토큰 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 기본 배치 5페이지 | 49.5초 | 7회 | 0회 | 1회 | 27,108 / 1,330 |
| 변경 배치 5페이지 | 46.7초 | 7회 | 0회 | 1회 | 29,171 / 1,353 |
| 변경 배치 + 알 수 없는 사실 2개 | 50.2초 | 7회 | 1회 | 1회 | 29,261 / 1,345 |

앞의 두 실행은 시작 후 질문에 답하거나 코드를 바꾸거나 작업/DB 값을 보정하지 않았다. 추가 질문이 동적으로 나타났을 때 실행기가 남은 계획을 취소하고 새 화면으로 복구했다. 다섯 페이지의 전송과 최종 접수 기록 1건씩을 확인했으며, 앱이 스스로 완료 판정했다.

마지막 실행은 대시보드 테스트 버튼으로 시작했다. 테스트 사용자의 가상 경험·회원 여부 두 문항이 확인함에 모인 것을 확인하고, 브라우저 UI 테스트가 일반 사용자 조작으로 두 답을 한 번에 전달했다. 이 실행의 사용자 역할 개입은 1회이며 코드·DB·프롬프트 유지보수 개입은 없었다. 이 행을 완전 무인 실행으로 세지 않는다. 확인함 대기는 약 1.8초였고, 추가 AI 호출 없이 저장된 계획에서 재개했다.

모델 추론 시간은 각각 46.4/44.2/45.7초였다. `browserMs`는 관찰·입력 검증 구간의 부분 계측이며 전체 브라우저 대기/전송 시간과 같지 않다. 전체 경과 시간에는 전송·조정 비용이 포함된다. 이 수치는 작은 합성 설문의 관측값이며, 이전 실서비스 설문과 문항/조건이 달라 직접적인 속도 향상 비율로 비교하지 않는다. 실제 플랫폼의 성공률·당첨률이나 비용 회수 가능성을 입증한 결과도 아니다.

## 실제 확인한 것

- 공식 ChatGPT 로그인, 플랜 사용 동의, 연결 복원, 계정의 모델 목록 조회, 실제 Responses 스트리밍 호출.
- 실제 ChatGPT 모델이 PNG 스크린샷과 보이는 요소를 읽고 다음 동작을 선택한다. 고정된 이벤트별 클릭 스크립트는 사용하지 않는다.
- 정상 배치와 바뀐 배치의 합성 이벤트에서 각각 8번의 AI 판단으로 완료했다. 팝업 닫기 → 스크롤 → 퀴즈 → 합성 문구 입력 → 필수 동의 → 제출 → 실제 로컬 접수번호 확인을 수행했다.
- 두 실행에서 모델 응답에 보고된 입력 토큰은 각각 26,302 / 26,725, 출력 토큰은 635 / 665였다. 금액이나 ChatGPT 크레딧으로 환산하지 않는다. 이는 한 환경의 관측값이며 실행마다 달라진다.
- Google 웹 검색 경로에서는 추가 인증 화면을 관측했다. 인증을 우회하지 않으며, 목록에서 직접 시작하는 경로를 제공한다.
- 실제 문화포털 공지 목록에서 에이전트가 글을 선택하고 포스터·본문을 확인하여 후보 2개를 저장했다. 탐색 도중 발견한 스크롤·관측 메모 문제를 수정하고 재개한 개발 검증이며, 처음부터 무개입 성공한 평가로 보지 않는다. 이후 SNS 세부 조건과 설문 접속·참여 조건을 추가 확인했고, 로그인 없이 참여할 수 있는 설문으로 진행했다.
- 실서비스 다단계 설문에서 사용자 답변을 선택하고 중간 응답을 전송한 뒤 다음 문항으로 진행했다. 사용자가 본인 정보와 동의를 직접 입력한 뒤 에이전트가 최종 제출을 실행했고, 새 완료 페이지의 명시적인 설문 완료 문구를 확인했다. SNS 게시·좋아요·팔로우와 당첨·경품 수령은 수행하지 않았다.
- 실제 최종 화면의 ‘설문이 완료되었습니다’ 표현이 기존 완료 판정에 없어 앱 상태는 결과 불명으로 남았다. 실제 완료 화면을 개발자가 확인해 로컬 응모 기록을 보정하고 확인 방식·화면 근거를 함께 저장했다. 인식 코드는 수정하고 합성 브라우저에서 재현·검증했다. 이 기록 보정을 새 코드의 무개입 실서비스 완료 판정으로 간주하지 않는다.
- 이 실서비스 테스트에는 개발자의 답변 전달·구체적 동작 검토·복구가 포함됐다. 사용자가 위임한 일반 평가 기준과 이미 제공한 선호를 재사용해 질문을 줄였지만, 대시보드의 구조화된 프로필/추천 정책이 자동 처리한 결과는 아니다. 긴 설문을 이어가기 위해 대기 중인 한 작업의 판단 한도를 로컬 유지보수로 120회에서 160회로 늘렸으며 누적 판단·사용량과 제출 상태는 유지했다. 당시 UI의 한도 추가 기능만으로 이 변경까지 처리할 수 없었다. 새 구현은 대시보드에서 20회씩 최대 300회까지 추가할 수 있다.
- API 키 제공자는 구현했으나 실제 API 키가 없어 전송/실패 분리 테스트까지만 검증했다.

| `src/model.ts` | 모델 목록, 이미지+도구 요청, SSE 종료 검증, 제한된 행동 스키마 |
| `src/browser.ts` | 전용 지속 Chromium, 화면/가시 요소 관찰, 좌표/요소 실행, 관측 갱신, 네트워크 범위 |
| `src/runner.ts` | 탐색/응모 루프, 누적 관측 메모, 승인·일시정지·재개·결과 불명 처리 |
| `src/store.ts` | SQLite 작업·후보·승인·응모·근거·합성 접수, 중복 방지, 중단 복구 |
| `src/server.ts` | 루프백 HTTP API, CSRF/Origin/Host 검사, 모델과 브라우저 작업 연결 |

| `src/demo.ts` | 실제 경품 없는 로컬 합성 이벤트 |

최초 탐색 시작점은 공개 목록 또는 Google 검색이다. AI가 현재 화면의 링크를 골라 이동하고 스크롤로 조건을 읽는다. 탐색 중에는 게시·폼 입력을 허용하지 않는다. 링크 클릭은 관측한 URL로 이동하며 페이지의 임의 클릭 핸들러를 실행하지 않는다. 기록할 참여 URL은 현재 페이지 또는 관측한 링크여야 한다. 이전에 관측한 URL로 돌아가 원문을 재확인할 수 있다. 마감 날짜만 알려진 경우 별도 날짜 필드에 저장하며, 해당 날짜 당일에는 정확한 종료 시각을 확인하기 전 자동 응모 준비를 막는다. 긴 포스터의 여러 구간에서 확인한 사실은 작업 메모로 유지한다.

실행기는 최신 관측 ID, URL, DOM/스크롤 변화와 유효 시간을 검사한다. 같은 프로필은 한 작업만 조작한다. 다른 작업을 실행한 뒤 이전 작업을 재개할 때는 해당 작업의 페이지를 복원하며, 결과 불명 상태에서는 자동 복원·재제출하지 않는다.

기존 단일 동작 경로의 승인에는 정확한 행동, 대상 라벨/링크, 입력 문구, 현재 폼 값, URL, 화면/폼 지문과 10분 만료를 묶는다. 새 자율 경로는 프로필·정책으로 입력하며 최종 검토는 실제 폼 구조/값에 결합한다. 화면이나 값이 달라지면 승인된 제출을 실행하지 않는다. 승인 폼 미리보기는 로컬 화면에서만 제공한다.

제출 가능 동작 전에 결과 불명 의도와 이전 화면 텍스트를 먼저 저장한다. 완료는 관측한 접수/완료 메시지 또는 새 게시 문구의 근거가 있어야 하며, 합성 이벤트는 서버의 실제 접수 기록까지 검사한다. 외부 서비스의 중복 방지나 정확한 완료 판독을 보장하는 범용 기능은 아니다. 애매하면 직접 확인을 요청한다.

## 자동 검증

로컬 자동 검증: 단위/정책 23개, 실제 브라우저 49개 통과. 타입 검사·포맷·빌드 확인. 브라우저 검사 중 설치된 Chrome 프로필 분리 1개는 해당 Chrome이 없는 환경에서 명시적으로 생략된다.

- 확인 대기 중 페이지 변경 시 승인 무효화

CI는 비밀정보 없는 임시 합성 데이터만 사용한다. 사용자의 ChatGPT/SNS 프로필, 원격 API 키 또는 실이벤트 응모는 CI에 사용하지 않는다.

## 실서비스 폼에서 보완한 동작

- 후보의 조건 재검토 기능은 참여 주소·날짜·남은 조건을 수정하며 이전 수집 근거와 검토 이력을 보존한다. 이미 응모가 시작된 후보는 수정하지 않는다.
- 사용자 답변은 작업별 context로 전달한다. 현재 질문에 해당하는 답만 사용하고 모르는 경험·선호를 추측하지 않는다. 같은 페이지의 미답변 문항을 먼저 읽고 함께 요청하도록 지시한다. 답변 갱신은 기존 승인을 무효화하며 결과 불명 상태를 해제하지 않는다.
- 다단계 폼의 `다음`도 전송 전에 의도를 저장한다. 같은 폼 URL에서 전체 페이지 수가 같고 현재 페이지 번호가 앞으로 이동해야 중간 진행으로 확인한다. 분기 때문에 여러 페이지를 건너뛰는 경우도 있으며 최종 접수로 처리하지 않는다.
- 서버가 POST로만 표시하는 중간 URL은 GET으로 재열면 오류가 날 수 있다. 사용자가 직접 연 현재 창으로 재개하는 별도 경로는 원점을 검사하고 페이지를 새로 불러오지 않는다.
- 화면에 보이지 않는 hidden input의 값 갱신은 시각적 변화에서 제외한다. 보이는 요소, 입력, 스크롤, input 타입 변경은 계속 관측을 무효화한다.
- 공개 링크 모음의 장식 애니메이션이 지속적으로 DOM revision을 바꾸어 스크롤까지 막던 문제를 재현했다. 읽기용 스크롤·대기 및 검증된 URL 열기는 같은 탭·URL·관측 ID·유효 시간을 확인하되 DOM revision 변화만으로 막지 않는다. 탐색 링크는 기존과 같이 관측한 주소로 이동하고 클릭 핸들러를 실행하지 않는다. 일반 클릭·입력·증거 판정은 계속 정확한 revision을 요구하며, 페이지가 바뀌면 읽기 행동도 거부한다. 실서비스 탐색 도중 수정·재시작한 개발자 개입이며 무개입 성공으로 기록하지 않는다.
- 네이티브 컨트롤의 실제 `required` 속성 외에 렌더링된 ‘답변 필수’ 표기를 읽는다. 필드에 연결된 `aria-describedby` 또는 질문 그룹의 설명을 수집해 확인함에서도 펼쳐 볼 수 있다. 설명이 바뀌면 기존 답변/폼 지문도 달라진다.
- 연락처 입력란이 하이픈 포함/제외를 명시하면 국내 휴대전화의 기존 숫자만 로컬에서 재배치한다. 국가번호 등을 추측해 만들거나 저장 프로필을 수정하지 않는다. 변환한 값도 비공개 값 목록에 넣어 화면 본문에 재표시될 때 마스킹한다. 임시 합성 폼에서 형식 적용·원본 보존·필수 표기·설명 변경·값 비노출을 검증했다.

- 디자인된 라디오/체크박스는 보이는 연결 label을 실제 클릭하여 선택한다. label이 숨겨졌거나 크기가 없으면 관측한 input 자체를 클릭한다. 두 경우의 선택과 중복 클릭 방지를 합성 Chromium 테스트로 확인했다. 강제 클릭이나 이벤트 직접 호출에 의존하지 않는다.
- 실서비스 평가 문항에서는 요소 클릭 실패 뒤 화면의 선택 원을 좌표로 클릭해 진행했다. 숨겨진 label 처리는 별도 합성 테스트로 재현·수정했으며, 이 수정의 실서비스 적용 결과까지 검증한 것으로 주장하지 않는다.
- 실서비스의 화면/폼 지문 변경으로 승인 동작이 실행되지 않은 경우에는 새 관찰로 검토를 갱신하고 응답 값이 같은지 확인한 뒤 진행했다. 이런 검토 갱신의 빈도와 추가 대기 시간도 후속 개선 대상이다.

### 추가 실사이트 탐색·응모 점검 (2026-11-08)

로그인된 Instagram의 공식 계정에서 이벤트 원문을 열고 프로필 링크 모음을 거쳐 Naver Form의 기간·응모 조건을 읽어 새 후보를 저장했다. 위 애니메이션 문제의 수정·앱 재시작과 개발자의 후보 검토가 포함됐다. 일반 검색 도구는 Google 인증 화면에서 멈춰 공식 계정에서 다시 시작했다. 이 과정은 완전 무인 탐색 성공이 아니다.

자율 폼 계획에서 이름·연락처는 로컬 프로필로 매핑되고, 공개 근거가 별도로 필요한 퀴즈·현재 참여 경로·최초 개인정보 동의 3문항이 확인함에 모였다. 개발자가 공개 정답 근거와 실제 탐색 경로를 확인해 전달했고, 사용자는 개인정보 동의와 저장된 정책의 최종 제출 검토를 각각 승인했다. 앱은 연락처 형식을 조정해 5개 항목을 묶음 입력하고 검토 후 한 번 제출했다. 공개 근거와 탐색 경로를 작업 간 검증된 사실로 자동 전달해 확인함 항목을 줄이는 기능은 후속 과제다.

실제 접수 화면에 ‘답변이 제출되었습니다.’가 표시됐으나 기존 완료 문구 판정이 이를 놓쳐 결과 불명 상태로 남았다. 문구를 판정기에 추가하고 단위·브라우저 테스트로 성공 표현과 부정/오류 표현을 검사했다. 재방문에서는 ‘이미 참여한 설문입니다.’가 표시됐고 재제출하지 않았다. 원래 제출 직후의 화면, 제출 전 의도와 단일 제출 이력을 개발자가 검토해 로컬 상태를 완료로 복구하고 증거·검토 방식을 남겼다. 이 보정은 새 코드의 무개입 실서비스 완료 판정으로 계산하지 않는다. 실제 응모 완료와 당첨·경품 수령은 별개다.

### 읽기 쉬운 제출 확인 UI

최종 확인함과 기존 단일 동작 확인 화면은 제출 대상 도메인, 질문별 입력값, 선택한 답을 목록으로 표시한다. 네이티브 label·질문 그룹의 제목·선택지 문구를 사용하고, 선택하지 않은 답과 내부 필드 이름은 기본 화면에서 제외한다. 원본 JSON은 ‘원본 데이터 보기’ 상세 항목을 펼쳤을 때만 보인다. 제출 승인과 폼 지문 검사는 그대로 유지한다.

가상 정보 5개를 넣은 대시보드를 PC·모바일 폭에서 확인했다. 질문별 표시, 선택한 답만 노출, JSON 접기/펼치기, hidden/password 제외, 모바일 가로 넘침 없음과 브라우저 오류 없음을 검사했다. 개인정보가 포함된 실제 입력 화면은 공개 검증 자료에 사용하지 않았다.

질문 일괄 처리, 대시보드 답변 UI, 추천 답변 자동 적용 설정과 제한된 예외 복구는 위 자율 경로에 구현했다. 더 넓은 SNS 과제, 비용에 따른 기회 포기 판단 등은 [실사용 피드백 계획](plan.md#8-실사용-피드백-왕복-최소화와-자율-응답)의 후속 범위다.

### 개발자 복구를 줄이는 후속 구현 (2026-11-08)

- 탐색에서 실제 관찰한 원문 텍스트·스크린샷·URL·시각을 후보에 보관하고 응모 계획에 전달한다. 퀴즈 답은 원문 ID와 정확한 인용을 검사한다. 검색 결과 요약만으로 근거 있는 답으로 승격하지 않으며 개인 경험·자격·동의에는 적용하지 않는다. 실제 방문 경로에서 확인한 유입 채널은 해당 문항에 재사용한다.

앱의 검색·후보 수집에서 이어진 두 페이지 퀴즈 응모의 최종 완료 화면을 확인했다. 저장된 프로필과 공개 퀴즈 근거를 사용하고, 개인정보 수집·이용 및 제3자 제공 동의 2건은 대시보드에서 사용자가 선택했다. 최종 검토 뒤 앱이 제출을 실행하고 새 화면의 ‘답변이 제출되었습니다.’를 `autonomous_visible_receipt`로 판정하여 완료 목록에 기록했다. 접수 상태나 완료 목록을 개발자가 수동 보정하지 않았으며, 실제 완료 기록은 총 3건이다. 당첨·경품 수령 결과는 확인하지 않았다.

실행 이력의 실제 전송은 첫 페이지 이동 1회와 마지막 제출 1회다. 입력 검증·계획 재실행 횟수를 별도 응모 횟수로 계산하지 않는다. 응모 준비와 결과 확인 작업의 모델 호출은 7회, 계측된 추론 시간은 약 48.6초였으며, 탐색 시간과 사용자 대기를 포함한 전체 소요 시간은 아니다.

전체 실행에는 중간 페이지 오인으로 인한 추가 검토, 사용자의 미제출 확인, 숨겨진 일시정지 카드 수정, 개발자의 일반 재개 API 호출이 포함됐다. 따라서 동의와 최종 확인만으로 끝난 실서비스 검증은 아직 통과하지 못했다. 진행 중에는 서버·브라우저를 교체하지 않았고, 후속 수정은 합성 브라우저에서 회귀 검증했다. 앞선 결과 불명 모아폼 건은 재제출하거나 완료 처리하지 않았다. 실제 참여 식별자·개인정보·화면 파일은 공개 저장소 밖에 보관한다.

접수 완료 후 실행 중인 작업이 없음을 확인하고 서버를 정상 종료·재시작하여 보류했던 진행 판독 수정까지 적용했다. 재시작 뒤 완료 목록 3건과 마지막 응모의 자동 판정 근거가 유지됨을 확인했다. 동의 위임 3단계는 별도 계획으로 기록했으며 현재 동의 정책은 변경하지 않았다.

## 현재 한계

- 실서비스 폼 3건의 완료 화면을 확인했고 마지막 1건은 앱이 완료를 판정·기록했다. 모두 전체 과정에는 개발자 개입이 있었으며, 플랫폼별 댓글·폼 완료 판독을 일반화해 검증하지 않았다. UI의 원문·대행 범위 확인만으로 플랫폼 허용을 자동 판정하지 않는다.
- 검색과 긴 이미지 이해는 모델·사이트 UI에 따라 실패할 수 있다. 이미지 기반 날짜/인원은 AI 해석임을 표시하고 실행 전 원문 확인이 필요하다.
- 페이지별 검색 버튼·본문 확장·iframe·파일 업로드·복잡한 여러 단계 폼은 제한적이다. 탐색 입력은 현재 Google 검색 도구 또는 시작 주소로 처리한다.
- 이벤트 간 중복은 정규화한 참여 URL과 주최자/제목으로 탐지한다. 표현이 다른 교차 채널 캠페인의 완전한 중복 판별은 보장하지 않는다.
- 시작일 별도 필드, 개인 자격 프로필, 선정 방식·발표 일정·쿠폰 데이터 모델은 후속 단계다. 미확인 조건은 blockers에 기록한다.
- 작업별 판단 한도와 실행 구간 15분은 있으며 예약 실행, 일별 비용 상한, 원화 비용 계산은 없다.
- 결과 불명 작업은 직접 확인 후 재개한다. 이미 시작/중지한 응모의 중복 잠금은 자동 해제하지 않는다.
- 개인정보는 보호된 로컬 파일에 보관한다. 암호화 키체인, 전면적인 페이지 PII 제거, 장기 증거 보관/삭제 정책은 후속 단계다. PNG와 본문은 선택한 AI 경로로 전송된다.
- 네트워크 요청은 HTTP(S), 공개 주소와 기본 포트로 제한한다. 이는 OS 수준 샌드박스가 아니며 악성 페이지의 모든 네트워크 공격을 차단한다고 주장하지 않는다.
- Node 24의 `node:sqlite`는 실행 시 experimental 경고가 표시될 수 있다.
