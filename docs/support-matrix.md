# 연결 및 응모 지원 범위

설계 기준일: 2026-11-07. 아래는 전체 목표이며 구현·검증 완료 목록이 아니다. 현재 실행 가능한 범위는 [구현 상태](implementation.md)를 참고한다.

브라우저 화면을 읽고 조작하는 기능은 첫 MVP의 필수 범위다. API가 없다는 이유만으로 브라우저 실행을 미지원으로 분류하지 않는다. 화면 조작의 기술 지원, 사이트에서의 사용 가능 조건, 실제 검증 상태를 각각 기록한다. 구체적인 실행 방식은 [브라우저 에이전트 설계](browser-agent.md)를 따른다.

## 1. 사용자와 앱의 역할

| 단계 | 사용자 역할 | 자동화할 부분 |
| --- | --- | --- |
| 공개 이벤트 발견 | 선호·지역·제외 조건 설정 | 브라우저 검색·스크롤·게시물 열기, 조건 해석, 중복 제거 |
| ChatGPT 연결 | 공식 로그인과 플랜 사용 권한 승인 | 토큰 갱신, 추론 요청, 오류별 처리 |
| API 키 연결 | 본인 API 프로젝트의 키 설정 | 선택한 프로젝트 경로로 호출·사용량 기록 |
| SNS 계정 가입 | 필요할 때 본인이 가입·약관 동의·본인인증 | 가입 안내·준비 상태 표시 |
| SNS 연결 | 전용 Chromium에서 최초 로그인; 공식 연동 또는 기존 브라우저 연결은 선택 | 세션 재사용, 화면 관찰과 승인된 작업 범위의 클릭·입력 |
| 재인증 | MFA·CAPTCHA·복구·새 권한 승인 | 해당 작업만 대기하고 재개 위치 보존 |
| 개인정보 제출 | 정확한 정보 제공, 대상·항목·용도 검토 | 허용된 필드 매핑·사전 입력·완료 기록 |

한 번의 ChatGPT 로그인이 Instagram, Google, Naver 로그인까지 제공하지 않는다. 매 실행마다 로그인할 필요는 없도록 설계하되, 서비스의 세션 만료와 재인증을 없앨 수는 없다.

## 2. 플랫폼별 초기 범위

| 출처/서비스 | 첫 범위 | 로그인과 실행 경계 |

| 기관·브랜드 공식 홈페이지, 검색 결과 | 브라우저 검색·목록 이동·이벤트 후보 발견·원문 조건 확인·발표 링크 기록 | 공개 정보도 출처별 자동 접근 조건 확인. 로그인 없이 가능한 부분부터 |
| Instagram | 브라우저 탐색 및 댓글·좋아요·팔로우 어댑터 구현. 현재 계정·대상·문구 승인과 새 화면 결과 확인 | 2026-11-11 기준 실제 이벤트 12건 완료, 그중 6건은 좋아요·팔로우·댓글 모두 확인. 일반 검색→조건 확인→묶음 승인 1회→실행→새 화면 증거까지 개발자 중간 개입 없이 완료한 전체 실행은 6건. 다른 복구 사례의 성공 구간과 실패 비용은 [검증 기록](implementation.md)에 별도 보존하며 장기 반복 성공률은 미검증. 로그인·접근 조건과 사이트 정책은 별도 확인 |
| YouTube | 공식 공개 검색 경로 검토, 이벤트 조건 분류, 사용자가 제공한 자료 해석 | API가 행동을 제공하더라도 사용자 주도성·이벤트 정책을 별도 검사. 경품을 통한 좋아요·구독 지표 늘리기를 자동 수행하는 기능은 범위 밖 |
| Google Forms | 브라우저에서 필드·단계·검증 오류를 읽고 입력·첨부·제출 결과 확인 | 응답 API의 제출 메서드 부재가 브라우저 폼 조작 부재를 의미하지 않는다. 폼별 로그인·접근 조건 확인 |
| Naver Form·기타 웹 폼 | 네이티브 필드 묶음 입력·다음 단계 이동·완료 확인; 네이티브 파일 필드의 사용자 선택 첨부 구현 | Naver Form 3건 접수 확인, 그중 2건은 앱이 완료 판정·기록. 완료 사례 한 건은 대시보드의 답변·동의와 최종 확인 외 개발자 중간 개입 없이 탐색부터 완료까지 연결. 후속 검증은 필수 수동 과제·탐색 한도로 새 접수 실패. 다른 폼·접근 조건으로 일반화하지 않음 |
| 기타 SNS | 공통 브라우저 도구로 탐색·클릭·입력하는 경로를 재사용 | 사이트별 접근 조건과 실제 UI 검증을 추가. API 엔드포인트 구현을 필수 조건으로 삼지 않음 |

SNS 전부를 먼저 연동하지 않는다. 선택한 이벤트가 필요한 연결을 요구할 때만 사용자에게 안내한다.

2026-11-10 탐색 보완: 네이버/Google 기본값과 인증 제한을 분리하고 반복 검색 시 다른 엔진이나 관측된 새 링크로 전환한다. 제외 사유·검색 이력·전환 횟수는 재개해도 유지한다. 인증을 풀거나 미관측 주소를 생성하지 않으며 기존 판단/일별 한도 안에서 자동 전환한다. 2026-11-12부터 운영탭에서 전환 상한을 1~100회로 설정할 수 있으며, 기존 설정의 기본값은 6회다. 새 작업·명시적 재개 시 적용하고 사용한 횟수·제외 이력은 초기화하지 않는다. 합성 검증과 실제 새 응모의 종단 결과는 [체크리스트](goal-checklist.md)에서 구분한다.

2026-11-08 사용자 재검증에서는 네이버의 전용 브라우저 종료 후 로그인 유지가 확인됐다. YouTube는 전용 Chromium·Chrome에서 로그인이 거부되고 일반 브라우저에서만 성공했다. 해당 환경에서는 YouTube의 로그인 필요 참여를 수동으로 처리하며, 일반 브라우저의 세션을 에이전트와 공유하지 않는다. 로그인 유지 확인과 실제 응모 완료 검증은 별개다.

## 3. 응모 유형과 구현 순서

| 응모 유형 | 지원할 기능 | 초기 실행 수준 | 단계 |
| --- | --- | --- | --- |
| 단순 댓글/응원 문구 | 조건에 맞는 문구 작성·입력창 찾기·타이핑·게시·게시 상태 확인 | 합성 화면에서 M0 검증, 실제 사이트는 구체적 작업 승인과 적용 조건에 맞춰 실행 | M0–M1 |
| 좋아요·팔로우·구독 | 화면에서 대상·현재 상태 확인 → 필요한 경우 클릭 → 상태 재확인 | 공통 실행기는 구현. 실제 실행 가능 여부는 플랫폼별 확인하며, 이미 완료된 상태에서 토글을 되돌리지 않음 | M0–M1 |
| 객관식·OX·단답 퀴즈 | 공개 근거를 찾고 화면에서 답 선택·입력 | 허용된 과제에서 실행; 불확실한 답은 사용자 확인 | M0–M1 |
| 간단한 응모 폼 | 화면에서 선택·단답·체크박스를 찾아 입력하고 오류를 보고 수정 | 대상과 전송 정보를 검토한 범위로 실행. 합성 폼부터 실제 폼으로 확장 | M0–M2 |
| 인증샷 첨부 | 대시보드에서 실제 파일 선택·해당 주최자 전송 허용·네이티브 파일 필드 첨부 확인 | 합성 검증. PNG/JPEG/PDF 5MB, 작업·문항·파일 해시에 한정. 자동 업로드 시도 후 상태가 사라지면 재전송 중단 | M2 구현 |
| 짧은 설문 | 사용자가 준 실제 선호·경험을 바탕으로 작성 보조 | 모르는 응답은 사용자에게 질문. 거주지·직업·경험을 추측하지 않음 | M2 |
| 여러 단계 혼합 | 화면 변화에 따른 행동 선택, 미완료 조건, 최종 제출 증거 관리 | 에이전트가 다음 단계를 수행하고, 실제 사용자 개입이 필요한 단계만 대기 | M2–M3 |
| 글쓰기·슬로건·이미지 등 창작 과제 | AI 사용 허용 조건 확인, 초안·제작 보조 | 검토 후 제출. 생성 도구 비용과 이용 조건을 별도 계산 | 이후 |
| 리그램·스토리·친구 태그 | 조건 해석과 수동 안내 | 초기 자동 실행 제외. 타인 반복 태그·대량 홍보를 생성하지 않음 | 이후 검토 |
| 구매·방문·실물 활동·신분증/세금 정보 | 조건을 표시하고 일반 추천에서 제외하거나 별도 분류 | 사용자 직접 처리. 구매나 활동 완료를 조작하지 않음 | MVP 제외 |

기술적으로 지원하는 브라우저 경로와 사용자 위임, 서비스 운영자의 공식 허용은 별도 항목이다. 인스타 브라우저 대행은 기본 꺼짐이며 사용자가 켜고 구체적인 작업을 승인해야 실행한다. 이를 플랫폼의 공식 승인으로 표시하지 않는다. 명시적 금지, 인증 장벽과 계정 제한을 우회하지 않는다.

## 4. 자동화 수준

- `automatic`: 허용된 탐색·분석·기록, 또는 검증된 경로에서 사용자가 구체적으로 승인해 둔 반복 행동.
- `approval_required`: 실행할 내용·대상·데이터가 준비되었고 사용자 확인 후 처리할 수 있는 행동.
- `manual`: 외부 서비스 UI에서 사용자가 직접 해야 하는 행동. 앱은 위치·체크리스트·증거를 관리한다.
- `unsupported`: 권한·정책 또는 검증된 실행 능력이 없어 실행하지 못하는 행동. 서비스 API 부재만으로 분류하지 않는다. 접근 제한이나 인증 장벽을 우회하지 않는다.

사용량 제한·로그인 필요·개인 응답 필요 등의 이유는 작업 목록에서 구체적으로 표시한다. 계정 경고나 제한이 발생하면 해당 어댑터를 멈추며, 저속 실행이나 부계정 사용을 제한 회피 보장으로 설명하지 않는다.

## 5. 보관과 증거

OAuth 토큰은 OS 자격증명 저장소 또는 보호된 로컬 비밀정보 저장소에 둔다. 브라우저 프로필·참여자 정보·인증샷·쿠폰은 기본적으로 소스 저장소 밖에 두고, 개발 중 예외 경로도 Git에서 제외한다. 비밀번호와 OTP를 모델 입력으로 전달하지 않는다.

성공 확인은 클릭 실행 자체와 구분한다. 제출 완료 페이지·접수 번호·공식 결과 등 관측 근거가 있어야 시스템 확인 상태로 기록한다. 사용자 완료 체크는 사용자 보고로 별도 표시한다.

2026-11-11: 승인된 네이티브 form action의 POST 응답과 연결된 동일 출처 완료 alert도 기록·검증한다. 오류·확인 질문·제출 전 메시지·외부 프레임은 완료 증거로 사용하지 않는다. 합성 검증 범위이며, 실제 배송지 응모 한 건은 제출 후 다른 출처로 이동해 명시적 증거를 놓쳤으므로 접수 미확인으로 유지한다. 과거 알림을 추정해 복원하거나 재제출하지 않는다.

## 6. 확인한 공식 자료

- [Meta Instagram API](https://www.postman.com/meta/instagram/documentation/6yqw8pt/instagram-api): 프로 계정의 미디어·댓글 관리 중심. 일반 소비자 계정의 자동 응모 경로로 간주하지 않는다.
- [Meta 자동 수집 설명](https://about.fb.com/news/2021/04/how-we-combat-scraping/): 허가 없는 자동 수집 제한에 대한 공식 설명. 구현 시 최신 약관과 실제 허용 경로를 재확인한다.
- [YouTube API 개발 정책](https://developers.google.com/youtube/terms/developer-policies): 사용자 행동은 명확히 사용자에 의해 시작되어야 하며, 사용자 데이터 쓰기에도 통제가 필요하다.
- [YouTube 이벤트 정책](https://support.google.com/youtube/answer/1620498?hl=en-GB): 이벤트를 통한 참여 지표 조작을 금지한다.
- [Google Forms 응답 API](https://developers.google.com/workspace/forms/api/reference/rest/v1/forms.responses): 공개된 메서드는 응답 조회용 `get`과 `list`다.
- [Playwright 인증 상태](https://playwright.dev/docs/auth): 인증 상태를 재사용할 수 있으며, 파일에 계정을 가장할 수 있는 민감한 쿠키 등이 포함될 수 있다. 저장소에 넣지 않는다.

2026-11-09 [모아폼 질문 종류 공식 안내](https://help.moaform.com/hc/ko/articles/900003444366)와 [답변하기 안내](https://help.moaform.com/hc/ko/articles/900004105306)를 확인했다. 공식 기능 종류와 앱 실행 지원은 구분한다. 현재 앱 어댑터는 렌더링된 텍스트 입력과 객관식 단일 선택에 한정하며, 복수 선택·순위·격자·파일은 지원하지 않는다. 자동화 허용이나 모든 설문의 응답 성공을 보장하는 근거로 이 문서를 사용하지 않는다.
