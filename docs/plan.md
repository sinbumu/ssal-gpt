# 쌀-GPT 구현 설계

설계 기준일: 2026-11-07. 현재 상태: 설계만 작성, 앱과 외부 연동 미구현.

## 1. 목적과 성공 기준

브라우저 화면을 보며 탐색·조건 이해·클릭·입력·완료 확인을 반복하는 에이전트를 만든다. 한국의 공개 이벤트 중 본인이 참여 가능한 기회를 찾고 실제 응모 흐름을 수행한다. 응모·당첨·수령·사용 결과를 기록해 운영비와 사람의 시간을 포함한 실익을 검증한다.

화면 기반 브라우저 조작은 제품의 핵심이다. 수집 API, 초안 생성과 수동 체크리스트만 있는 앱은 MVP 목표를 달성하지 못한 것으로 본다. 상세 구조는 [브라우저 에이전트 설계](browser-agent.md)를 따른다.

첫 경품 수령은 동작 사례이며 수익성의 증거로 일반화하지 않는다. 결과 미발표·발표 확인 불가를 낙첨으로 계산하지 않는다. 개발 시간과 일상 운영 시간을 별도로 기록한다.

## 2. 확정 요구사항

1. 공식 ChatGPT 로그인 / 플랜 사용량 연동과 OpenAI API 키 연동을 모두 첫 MVP에 포함한다.
2. 실행은 채팅 앱과 독립적이며 주기·시간대·동시성·작업량·예산을 설정으로 조정한다.
3. 처음 필요한 서비스에만 가입·로그인·권한 승인을 요청한다. 전 플랫폼 계정 가입을 초기 설치 조건으로 만들지 않는다.
4. 공개 검색·홈페이지·사용자 제공 자료로 탐색을 시작할 수 있어야 한다.
5. 응모를 개별 행동으로 분해하고 자동/사용자 승인/사용자 직접 수행/미지원 상태를 표시한다.
6. 사용자 개입 대기 중에도 독립적인 다른 이벤트 작업은 진행한다.
7. 참가 제한은 계정 수가 아닌 이벤트 규칙의 참가자 단위로 검사한다.
8. 개인정보·인증정보·쿠폰은 공개 저장소와 분리한다.
9. 전용 Chromium에서 스크린샷 관찰·스크롤·클릭·입력·다시 관찰하는 실행 루프를 첫 MVP에 포함한다.
10. ChatGPT 로그인 경로에서도 화면 이해와 로컬 브라우저 도구 실행이 함께 동작해야 한다. 네이티브 Computer Use 도구가 없어도 앱 자체 실행기로 구현한다.
11. 서비스 API와 브라우저 UI는 별개 실행 경로다. API 엔드포인트 부재만으로 UI 행동을 수동 전용으로 분류하지 않는다.

## 3. 세 종류의 연결

### AI 연결

- ChatGPT OAuth: 공식 앱별 등록·권한 동의 흐름을 사용한다. 로그인 성공 후 플랜 사용 권한과 실제 모델 호출 가능 여부를 별도로 검증한다.
- OpenAI API 키: 사용자가 선택한 API 조직·프로젝트의 과금 경로를 사용한다.
- 둘은 독립된 제공자다. 인증 실패·사용량 한도 발생 시 유료 경로로 자동 전환하지 않는다.
- ChatGPT 연동이 기존 ChatGPT 대화, SNS 로그인, 이 개발 환경의 플러그인과 도구를 자동 제공한다고 가정하지 않는다.

### SNS·폼 연결

- 화면 조작을 기본 실행 경로로 두고, 검증된 공식 API는 보조 경로로 사용할 수 있다.
- 기본은 앱 전용 Chromium 지속 프로필이다. 필요한 사이트에서 사용자가 직접 최초 로그인한다.
- 기존 브라우저는 사용자가 선택한 프로필·탭만 연결하는 별도 모드로 확장한다. 디버깅 접근이나 확장 설치가 필요하면 사전 연결 단계로 명확하게 다룬다.
- 로그인 상태 재사용은 기술적 기능이다. 해당 서비스에 대한 자동 접근·수집·제출 허용을 뜻하지 않는다.
- 비밀번호·OTP·CAPTCHA·복구·약관 동의는 사용자에게 맡긴다. 세션 만료 시 해당 연결만 멈춘다.
- 일반 브라우저의 기존 쿠키·로그인을 몰래 가져오지 않는다. 다른 기기·서버로 이동할 때 로그인 유지가 보장되지 않는다.

### 개인 참여 정보

- 사용자가 명시한 이름, 연락처, 지역, 응모에 필요한 자격과 실제 선호만 저장한다.
- 제출 전 이벤트 주최자·최종 도메인·전송 항목을 보여준다. 새 필드·목적·수신자가 생기면 기존 승인과 분리한다.
- 연락처를 모델에 보낼 필요 없이 필드 자리표시자를 해석한 후 로컬에서 값을 채울 수 있도록 한다.
- 마케팅 수신 등 선택 동의를 자동 체크하지 않는다.

## 4. 실행 구조

```text
Scheduler → Persistent job queue → Worker
                                  ├─ Task goal / eligibility / authorization
                                  ├─ Browser agent loop
                                  │    Observe: screenshot + visible element refs
                                  │       ↓
                                  │    Decide: ChatGPT OAuth / OpenAI API
                                  │       ↓
                                  │    Execute: scroll / click / type / upload
                                  │       ↓
                                  │    Verify: fresh observation → next decision
                                  ├─ Pause / manual takeover / recovery
                                  ├─ Optional search / service API adapters
                                  └─ Result / claim tracking and usage records
                         SQLite + protected local credential/profile storage
```

AI가 판단에 필요한 순간만 호출한다. 날짜 비교, 예산·작업량 검사, 상태 전이, 중복 제거, 재시도는 코드로 처리한다. 공식 ChatGPT 연동의 `background` 필드 지원 여부와 앱 자체의 스케줄 실행은 별개다. 장기 실행은 이 앱의 프로세스가 담당한다.

### 기술 선택 제안

TypeScript + Node.js + SQLite + Playwright + 로컬 작업 화면을 기본 구현 제안으로 둔다. Playwright는 Chromium 화면 관찰과 마우스·키보드 실행을 담당하고 AI는 목표와 현재 관측을 바탕으로 행동을 선택한다. 화면과 DOM/접근성 정보를 함께 활용하되, 화면을 모델이 실제로 이해하고 좌표 행동을 수행하는 경로도 반드시 구현한다. 아직 의존성·버전·패키지 구조를 확정하거나 설치하지 않았다.

운영은 로컬 PC에서 시작한다. PC가 잠들거나 프로세스가 종료되면 실행이 중단되므로, 작업은 재시작 후 이어져야 한다. 이후 사용자 소유 상시 실행 환경을 검토한다. 공개 저장소의 CI에는 개인 SNS 세션이나 쿠폰을 넣지 않는다.

## 5. 이벤트와 행동 모델

이벤트는 필요한 행동들의 의존 관계로 표현한다. 예: 자격 확인 → 요구된 SNS 행동 → 실제 인증샷 준비 → 폼 작성 → 제출 확인. 각 행동은 브라우저 에이전트가 수행하거나 실제로 사용자 개입이 필요한 경우 대기한다. 단순 클릭·입력을 처음부터 수동 작업으로 고정하지 않는다.

행동 종류:

- `read_source`, `answer_quiz`, `draft_comment`
- `like`, `follow`, `subscribe`, `post_comment`, `share_post`
- `fill_form`, `upload_evidence`, `submit_form`
- `check_result`, `claim_reward`, `record_redemption`

각 행동에 아래 정보를 저장한다.

- 원문 조건과 근거 위치, 필수/선택 여부, 선행 행동
- 플랫폼·필요 계정·지원 어댑터와 허용 근거
- 실행 모드: `automatic`, `approval_required`, `manual`, `unsupported`
- 전송 데이터 항목, 대상 URL·도메인, 게시할 정확한 내용
- 완료 증거와 관측 시각; 사용자 완료 확인은 시스템 검증과 구분

글의 조건이 바뀌거나 대상·답변·개인정보가 바뀌면 해당 승인을 무효화한다. 한 이벤트의 승인이 다른 이벤트나 데이터 전송까지 확대되지 않게 한다. 필수 행동이 미지원이면 자동 참여 가능으로 표시하지 않는다.

### 기록할 엔터티

- `Event`: 대표 URL, 여러 출처 URL, 주최자, 일정, 경품, 선정 방식, 참가 제한, 근거, 신뢰도
- `Participant`: 로컬 참가자 식별자와 명시된 자격 정보. 인증 토큰과 분리
- `Connection`: 제공자, 로컬 비밀정보 참조, 허용 범위, 유효 상태
- `Task`: 행동, 의존 관계, 상태, 재시도 정책, 시간·사용량
- `Observation` / `BrowserAction`: 브라우저·탭·관측 ID, 화면 좌표 체계, 관측 근거, 실행한 도구, 전후 상태와 검증 결과. 모델의 숨은 사고과정은 저장하지 않음
- `Approval`: 이벤트·행동·대상·데이터·내용에 묶인 승인과 만료
- `Submission`: 중복 방지 키, 요청·응답 증거, 확인된 완료 시각
- `Outcome`: 발표 대기/당첨/낙첨/확인 불가, 근거와 수령 기한
- `Reward`: 수령 여부, 만료일, 액면가, 실제 사용 가치 또는 판매대금

같은 캠페인의 여러 SNS 게시물은 하나로 묶는다. 재응모 허용이 명확한 이벤트만 라운드/허용 기간을 중복 방지 키에 포함한다.

## 6. 복구와 비용

- 타임아웃 뒤 제출 여부를 모르면 `submission_unknown`으로 기록하고 확인 작업으로 전환한다. 재제출을 자동으로 반복하지 않는다.
- 로그인 재확인이 필요하면 해당 연결을 `needs_login`으로 바꾸고 다른 독립 작업은 계속한다.
- CAPTCHA·본인인증 등은 `needs_user`로 전환한다. 우회하지 않는다.
- 일시적 서버 오류는 제한된 횟수의 지연 재시도, 권한·자격·과금 오류는 원인별 중지로 처리한다.
- 대기 중 반복적인 모델 호출을 하지 않는다. 같은 원문 해시는 결과를 재사용하고 변경 시 재분석한다.
- 제공자별 토큰·도구 사용량, 관측 가능한 비용과 추정값을 구분해 저장한다. 주간 한도나 API 금액을 임의로 크레딧과 환산하지 않는다.
- 작업별 시간·호출 횟수·행동 횟수 및 일별 예산을 앱에서 제한한다. 공급자가 지원하지 않는 출력 제한 필드에 의존하지 않는다.
- 발표 확인 실패는 낙첨이 아니다. 개인정보와 쿠폰은 로그에서 마스킹한다.
- 사용자 수동 조작·재시작·화면 변경 후에는 기존 클릭 좌표를 재생하지 않고 현재 화면을 다시 관찰한다.
- 프로필/탭의 쓰기 작업은 잠금으로 직렬화한다. 사람이 제어권을 가져가면 예약된 브라우저 행동을 취소한다.

## 7. 구현 순서와 완료 조건

### M0: 인증 두 경로 + 화면 기반 브라우저 실행 — 첫 필수 단계

- 공식 ChatGPT 연결 등록·권한 검사·모델 조회·실제 추론 성공·토큰 갱신 처리.
- API 키 경로로 같은 브라우저 작업을 실행할 수 있도록 제공자를 분리. 사용자가 선택한 경로를 명확히 표시.
- 전용 Chromium을 열고 화면을 AI에 전달한 뒤 스크롤·클릭·입력·다시 관찰하는 실제 루프를 구현.
- 합성 이벤트 화면에서 팝업·스크롤 아래 조건·퀴즈·응모 폼·완료 확인을 수행. 고정된 페이지별 동작 스크립트만으로 성공 처리하지 않음.
- 레이아웃 변화, 수동 개입, 성공 응답 유실을 포함한 평가. 화면 좌표 행동과 요소 참조 행동 모두 확인.
- 한도/권한 실패 시 중지하고 유료 경로로 넘어가지 않는지 확인.
- 실행 기록을 저장하고 앱 종료 후 이어가기.
- 제공자별 호출에 필요한 도구만 구현한다. API 호출 도구나 실제 인증이 없으면 미검증 상태를 표시한다.

### M1: 브라우저 탐색·조건 이해와 SNS 행동 검증

- 브라우저에서 검색·목록 스크롤·게시물 열기·본문 확장·여러 탭 이동을 수행. 사용자 제공 자료와 검색 API도 보조 입력으로 지원.
- 마감, 필수 과제, 자격, 경품, 발표 방식 추출과 근거 표시.
- 댓글·퀴즈 작성, 중복 제거, 발표 일정. 클릭·텍스트 입력·게시 확인은 브라우저 실행기 대상 행동으로 구현.
- 실제 사이트는 접근 조건·계정·사용자 권한을 확인한 범위에서 검증한다. 검증된 행동과 아직 검증하지 않은 행동을 구분해 표시.
- 검수 예제로 누락·날짜 해석·교차 채널 중복을 평가.

### M2: 여러 단계 응모와 증거

- 자체 테스트용 폼에서 단답·선택·다중 선택·실제 증거 파일 첨부를 검증.
- 허용과 구현 경로가 확인된 실서비스로 확장. 사이트별 API 대신 화면 관찰과 도구 실행으로 필드를 처리하고, 필요한 사이트별 힌트만 추가.
- 제출 직전 정확한 내용·대상·개인정보를 검토하고 완료 증거 확인.
- 재시작·타임아웃·중복 클릭이 이중 제출을 만들지 않는지 테스트.

### M3: 주기 실행과 결과·경품 관리

- 검색/결과 확인 일정, 사람 개입 대기열, 연결 만료 알림.
- 허용된 출처의 발표 확인, 또는 사용자의 공식 발표/DM 확인 결과 입력.
- 당첨 확인, 수령 기한과 쿠폰 만료, 실제 실현 가치 기록.
- 사람이 들인 시간, 누락/무효, 비용과 성과 보고.

### 이후

기존 사용자 브라우저 연결, 검증된 플랫폼별 실행 힌트, 승인된 반복 작업, 허용된 창작 과제, 사용자가 소유한 상시 실행 환경을 순서대로 검토한다. 브라우저 에이전트 자체를 후속 선택 기능으로 미루지 않는다. 모든 SNS의 모든 이벤트가 무인 실행된다는 보장은 하지 않는다.

## 8. 설계 근거

공식 문서는 변경될 수 있으므로 구현 직전에 다시 확인한다. 아래 사실은 기능의 현재 계정별 사용 가능 여부를 보장하지 않는다.

- [ChatGPT plan usage 개요](https://developers.openai.com/siwc/token-sharing-open-source): 오픈소스·로컬 앱이 별도 동의를 통해 적격 Responses 요청에 플랜을 사용할 수 있는 공식 경로.
- [ChatGPT 연동 제한](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations): 직접 HTTP 경로는 `store: false`, `stream: true`를 요구하며 일부 필드·호스팅 도구를 지원하지 않는다. 브라우저 실행과 작업 상태는 앱이 담당한다.
- [ChatGPT 연동 오류 복구](https://developers.openai.com/siwc/token-sharing-open-source/errors-and-recovery): 플랜 사용 권한을 확인하고, 한도·부적격·일시적 오류를 구분한다. 실제 결과로 접근을 검증한다.
- [ChatGPT API 크레딧 혜택](https://developers.openai.com/api/docs/guides/chatgpt-api-credits): 적격 구독의 별도 API 조직 연결 혜택이며, 앱의 OAuth 플랜 사용과 다른 경로다.
