# 화면 기반 브라우저 에이전트

설계 기준일: 2026-11-07. 첫 MVP 구현 완료, 실서비스 검증은 진행 중. 현재 범위는 [구현 상태](implementation.md)를 참고한다. 이 문서는 첫 MVP의 필수 동작과 검증 기준을 정의한다.

## 제품의 중심

쌀-GPT는 브라우저에 표시된 내용을 이해하고 다음 행동을 선택해 작업을 수행하는 에이전트다. 화면과 조건이 변하면 관찰을 갱신해 계획을 바꾼다. 사이트 API 호출이나 고정된 클릭 순서만으로 이 요구사항을 충족했다고 보지 않는다.

브라우저 실행 기능은 서비스 API 유무와 독립적으로 구현한다. 서비스에서 허용되는 접근, 이벤트 참여 조건, 사용자 권한은 실제 외부 실행 시 따로 검사한다. 공식 API가 없는 것과 화면에서 조작할 수 없는 것을 혼동하지 않는다.

## 1. 기본 브라우저와 기존 브라우저

| 방식 | 구현 순서 | 동작 |
| --- | --- | --- |
| 전용 Chromium + 지속 프로필 | 첫 MVP | 보이는 창에서 사용자가 최초 로그인. 앱이 소유한 탭·프로필에서 실행하며 재시작 후 세션 재사용 |
| 설치된 Chrome + 별도 앱 전용 지속 프로필 | 구현 (2026-11-08) | 공식 Chrome 채널 선택. 기존 Chromium 및 일상 Chrome의 프로필과 분리하며 서비스의 로그인 수락은 별도 확인 |
| 사용자가 명시적으로 연결한 기존 Chrome/Chromium | 구현·합성 검증 (2026-11-09) | 선택한 탭·프로필만 제어. 연결 방식과 권한을 명시하고 작업 외 탭은 읽지 않음 |

기존 Chrome 연결은 사용자가 준비한 `http://127.0.0.1:포트` CDP 연결을 사용한다. 목록에서 고른 탭에만 관측·입력·네트워크 검사를 설치한다. 연결 목록에는 제목과 주소만 표시하며 본문·쿠키·다른 탭 입력은 읽지 않는다. 연결 해제는 창을 닫지 않고 제어 연결만 끊는다. 이 모드는 탭 하나에 한정되며 독립 작업 탭과 별도 정답 조사 탭은 전용 브라우저 모드에서 지원한다. 앱 재시작 후에는 직접 재연결한다. 기본 프로필을 복사하거나 실행 중인 같은 프로필을 다른 브라우저 프로세스가 동시에 열지 않는다. 제어 포트를 공개 네트워크에 노출하지 않는다.

일반 브라우저로 URL을 여는 수동 대안은 기존 Chrome 연결 기능과 다르다. 앱이 해당 창을 관찰·조작하거나 인증 상태를 공유하지 않는다. Google이 자동화 브라우저의 로그인을 거부하는 경우 이 수동 경로로 안내하며, 자동화 식별을 숨기는 플래그나 쿠키 이전으로 해결하지 않는다.

초기 브라우저는 화면이 보이는 모드로 실행한다. 사용자는 현재 작업, 최근 행동, 판단의 짧은 근거와 결과를 보고 일시정지·중지·직접 조작할 수 있어야 한다. 무화면 실행은 이 기본 경로를 검증한 뒤 선택 기능으로 검토한다.

## 2. 모델과 실행기의 분리

```text
사용자 목표 + 허용 범위 + 이벤트 상태
                 ↓
관찰기: 현재 탭의 스크린샷, URL, 보이는 요소, 현재 작업 상태
                 ↓
AI: ChatGPT 로그인 또는 API 키 → 다음 행동과 예상 결과
                 ↓
실행 검사: 대상·관측 유효성·승인·예산·중복 여부
                 ↓
브라우저 실행기: 스크롤 / 클릭 / 입력 / 키 / 첨부 / 탐색
                 ↓
새 화면 관찰 → 결과 검증 → 계속 / 수정 / 사용자 개입 / 완료
```

ChatGPT 로그인 경로의 이미지 입력과 사용자 정의 도구를 이용해 이 구조를 구성할 수 있다. 네이티브 Computer Use 도구를 이 경로가 제공한다고 가정하지 않는다. 앱이 제한된 브라우저 도구를 제공하고 실행 결과를 모델에 전달한다. 이 조합의 실제 동작은 M0에서 사용 가능한 모델·권한으로 검증한다.

화면 이해가 가능한 모델인지와 도구 호출이 되는지 연결 직후 합성 자료로 확인한다. 실패 시 지원하지 않는 기능을 명시하고, 사용자 모르게 유료 API로 전환하지 않는다.

## 3. 관찰

한 번의 관찰에는 아래 항목을 묶는다.

- `profile_id`, `tab_id`, `observation_id`, 관측 시각
- 현재 URL·원점·페이지 제목·viewport 크기·스크롤 위치
- 실제 viewport 스크린샷과 이미지 크기·CSS 좌표 사이의 변환 정보
- 현재 화면에서 보이는 요소의 역할·텍스트·경계 상자·그 관찰에 한정된 참조
- 직전 행동, 관측된 결과, 현재 목표와 아직 남은 조건

스크린샷은 모델이 실제로 읽는 입력이다. DOM/접근성 정보는 정확한 요소 선택과 텍스트 읽기의 보조 자료로 사용한다. 이미지·커스텀 UI처럼 요소 정보가 부족한 경우에는 스크린샷을 기준으로 좌표를 선택한다. 모델이 관측하지 않은 selector나 버튼 위치를 만들어내지 못하게 한다.

외부 웹페이지의 문구는 작업 자료다. 실행 권한을 확대하거나 자격증명을 요청하거나 도구 정책을 바꾸는 지시로 취급하지 않는다. 필요한 탭과 영역만 모델에 전달한다. 로그인·OTP 입력 중에는 모델 관찰을 중지하고, 입력 완료 후에도 자격증명이 관측 자료에 섞이지 않게 한다. 개인 정보와 쿠폰이 보이는 화면은 로컬에서 전달 범위를 제한한다.

## 4. 최소 브라우저 도구

아래 이름은 앱 내부 인터페이스 제안이며 현재 설치된 도구 이름이 아니다.

| 도구 | 목적 | 실행 전제 |
| --- | --- | --- |
| `browser.observe` | 화면과 보이는 요소 관찰 | 명시된 탭만 |
| `browser.navigate` | URL 열기·뒤로가기·탭 전환 | 작업 범위와 이동 대상 확인 |
| `browser.scroll` | 세로/가로 스크롤 | 현재 탭·viewport 확인 |
| `browser.click` | 요소 참조 또는 화면 좌표 클릭 | 같은 최신 관찰에 묶인 대상 |
| `browser.type` | 텍스트 입력 | 입력할 필드·포커스 확인; 비밀정보는 모델 인수에 포함하지 않음 |
| `browser.press_key` | Tab·Enter·Escape 등 | 포커스와 제출 부작용 확인 |
| `browser.select` | 선택 항목 변경 | 관측된 선택지에 한함 |
| `browser.upload` | 승인된 실제 증거 첨부 | 로컬 증거 저장소의 허용된 파일 식별자만 |
| `browser.wait_for` | 로딩·상태 변화 대기 | 시간 제한·취소 가능 |

모델에 임의의 JavaScript 실행, 파일시스템 전체 접근 또는 네트워크 요청 권한을 주지 않는다. 필요한 브라우저 기능은 실행기가 좁은 도구로 구현한다. 사이트별 힌트나 검증된 locator는 안정성을 높이는 보조 수단이다.

## 5. 실행·확인·사용자 개입

- 한 단계의 판단은 구체적인 대상·행동·기대 결과를 포함한다. 장문의 내부 사고과정을 저장하지 않는다.
- 의미 있는 화면 변경 뒤에는 새 관측으로 결과를 확인한다. 오래된 좌표·요소 참조는 재사용하지 않는다.
- 이미 팔로우/좋아요 등 원하는 상태라면 다시 클릭해 취소하지 않는다. 목표 상태와 현재 상태를 비교한다.
- 승인된 작업 안의 통상적인 스크롤·입력마다 승인을 반복하지 않는다. 게시·제출의 내용·대상·데이터와 작업 범위가 달라지면 별도로 확인한다.
- 로그인, 추가 인증, 모르는 개인 응답, 작업 범위 밖의 동의 등 실제 사용자 개입이 필요한 경우에만 `needs_user`로 전환한다.
- 사용자가 직접 조작하면 모델의 대기 중 행동을 취소하고 브라우저 제어권을 넘긴다. 재개 시 새 관찰부터 시작한다.
- 단일 프로필/탭은 한 실행 주체만 변경한다. 다른 이벤트 분석 등 독립 작업은 계속할 수 있다.
- 클릭 성공, 네트워크 요청 발생, 실제 제출 완료를 구분한다. 결과가 불명확하면 기존 댓글·접수 상태 등을 확인하고 이중 제출하지 않는다.
- 접근 제한, 인증 장벽과 계정 경고를 우회하는 기능은 만들지 않는다. 해당 실행을 멈추고 상태를 표시한다.

## 6. 첫 데모의 완료 조건

로그인과 브라우저 작업이 함께 성공해야 MVP의 핵심 검증을 통과한다.

1. 공식 ChatGPT 로그인으로 플랜 사용 권한과 이미지·도구 호출을 확인한다.
2. 전용 Chromium에서 자체 테스트용 이벤트 화면을 연다.
3. 모델이 화면을 보고 팝업을 닫고 스크롤하여 이벤트 조건을 읽는다.
4. 퀴즈 선택·댓글 입력·선택 항목·다음 단계 이동을 실제 화면에서 수행한다.
5. 제출 전에 확인이 필요한 내용은 보여주고, 승인된 범위에서 테스트 제출을 수행한다.
6. 완료 화면을 다시 관찰하고 테스트 서버의 실제 접수 결과와 대조한다.
7. 같은 흐름을 API 키 제공자로도 실행할 수 있다. 어느 경로를 썼는지 명확히 표시한다.
8. 중지·재시작·수동 개입 후 새 관측으로 이어가며 중복 제출하지 않는다.

평가용 화면에는 레이아웃 이동, 스크롤 아래 조건, 임의 팝업, 필수 필드 오류와 응답 지연을 포함한다. 모델은 화면에 보이지 않는 정답·테스트 fixture 내부 상태를 보지 못하게 한다. 평가기는 실제 접수 결과를 따로 확인한다. 모델이 성공이라고 말하거나 정해진 좌표 스크립트가 끝났다는 이유만으로 통과시키지 않는다.

평가 지표는 과제 완료율, 사람 개입 횟수, 잘못된 대상 클릭, 중복 제출, 평균 행동 수·시간·모델 사용량이다. 합성 환경 통과와 실제 SNS 검증 결과는 별도로 보고한다.

## 7. 참고한 공식 문서

- [OpenAI ChatGPT 연동 제한](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations): 지원 모델의 이미지 입력과 사용자 정의 도구를 활용할 수 있고 네이티브 Computer Use는 제공하지 않는 경로다. 위 브라우저 실행 구조는 이 기능들을 조합한 설계 제안이며 동작 검증 전이다.
- [Playwright Page](https://playwright.dev/docs/api/class-page): 페이지 관찰과 스크린샷·키보드·마우스 실행 기능.
- [Playwright BrowserType](https://playwright.dev/docs/api/class-browsertype): 브라우저 실행, 지속 프로필과 기존 인스턴스 연결 기능.
